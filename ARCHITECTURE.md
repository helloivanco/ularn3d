# Architecture

## Runtime

The game is a static Vite application with an optional offline Electron desktop host. Three.js renders the world with a perspective camera, shadows, fog, procedural meshes, and pointer controls. There is no application backend.

The public website keeps browser play at `/` and offers a separate static guide at `/about/`. `public/about/index.html` and its stylesheet are copied directly into the build; `vite.config.js` uses multipage mode and directory-index middleware so development and preview serve the guide at its production URL. `public/site-runtime.js` identifies the browser or `ularn:` desktop host and hides web-only download controls inside the desktop application.

`public/engine/` contains the original JavaScript Larn/Ularn source and assets. `scripts/build-engine.mjs` concatenates its classic scripts in upstream load order, includes the shared score service, then appends `src/bridge.js`, producing `public/engine/game.js`. It also generates public JS/JSON score configuration from `scoreboard.config.json` and optional Vite environment overrides, rejecting privileged keys. Both entry points load that configuration before initializing the service. The Vite build copies this bundle and other public assets into `dist`.

## Authority and state

The original engine owns level generation, player attributes, items, monsters, movement, turns, combat, spells, shops, traps, time limits, and endings. The 3D UI sends ordinary engine commands through `window.ularn.key()`. It does not independently simulate gameplay. The bridge applies one explicit balance adjustment for this edition: new lemming placements are capped at four per floor, movement and melee attacks cannot spawn offspring, and melee dispatches a lemming through the normal damage/death/loot/experience path in one attempt. The movement adapter then advances into that cleared square within the same engine action, preserving normal terrain/loot handling and one turn per step. It disables the extra advance while confused or time-stopped. Harmless lemmings cannot set attack-interruption flags or suppress nearby interactions, rest or native exploration. New cave floors seed a rodent when the ordinary population contains none. The random-monster adapter checks for arrivals every 24 actual expedition turns: it refills an empty cave or uses a 60% chance for an additional arrival, still under the cap. Placement prefers empty floor 3–7 cells from the hero and falls back to more distant empty floor. These additions do not run in town/volcano, under time stop, after endings or when the species is genocided. The saved player turn count supplies the cadence, so no new save fields or wall-clock timers are needed. A weak set distinguishes existing creatures being relocated from new placements; restored swarms above the cap are preserved. The vendored classic scripts and classic rules remain intact.

The bridge exposes `start`, `snapshot`, `key`, `openToward`, `save`, `hasSave`, `interruptTravel`, and `setAutoLoot`. Snapshot adds inventory slots/equipment, actual effect timers, map glyphs, weapon families, and weakly held monster presentation identities/facing. Visible creatures include a `harmless` capability derived from the actual engine species; a mimic presented as a lemming stays hostile. The navigation helper defaults to blocking creatures without this capability. Known, unmasked staircase tiles also receive direction and blocked-state metadata derived from the existing `stairs.js` dead-end conditions; blocked stair names append `(dead end)`. Snapshot construction filters unexplored tiles, hidden traps, invisible monsters, and blindness using the engine's knowledge flags and visibility checks. The presentation never treats its meshes as authoritative collision data.

`src/world.js` renders known tiles and follows the player. `src/materials.js` caches procedural surface maps and materials. `src/models.js` builds the player, buildings, creature families, terrain objects, and items from local procedural geometry. `src/main.js` owns HUD updates, input, contextual-menu layout, known-tile pathfinding, minimap, camera controls, sound, and start/pause/help flows. Clicking a staircase underfoot dispatches the original `<` or `>` command according to its tile identity. Stair models display direction-specific steps or rubble and a cross for intentional dead ends. The usable Volcano 1 exit is a separate shaft tile labeled `SURFACE SHAFT`; its behavior is not inferred from the blocked staircase rules.

`src/creatures.js` defines an exact-ID registry for all 65 Ularn species. Family rigs use cached, shared geometry with species-specific proportions and details. Actor groups preserve bridge identity across movement, rotate toward engine facing, and animate their joints without simulating turns. Mimics and hidden creatures use only the bridge's already-filtered presentation identity. Class-specific heroes and equipment families are built in `src/models.js`. Weapons use cached, merged templates, including seven distinct dagger/sword designs; changing between sword IDs updates the held model even within the same family. A shoulder/hand hierarchy keeps the blade attached to the animated arm. `src/hero-animation.js` runs one retargetable action with 55 ms wind-up, 105 ms contact and 330 ms settling, alternating closely spaced slashes. An eight-sample fixed ribbon and ten-point impact buffer supply bounded feedback. Only resolved combat events start actions; waiting does not simulate an attack. Misses and unseen targets produce no impact spark. Pause, hiding, context loss, equipment changes and floor transitions reset the pose. Reduced motion skips both swing and transient feedback. Contact audio uses the same 105 ms timing without delaying engine actions. Legacy sprites and the former lemming illustration remain bundled reference/classic assets.

`src/navigation.js` owns known-tile shortest-route planning and the cancellable held-input timer. Route planning, step revalidation and visible-danger checks share the same hostile-creature predicate, so harmless lemmings remain traversable while enemies and known hazards still block travel. The first directional action is immediate, the initial repeat delay is 220 ms, and subsequent steps run every 140 ms. A delayed timer issues one action without catch-up. `src/main.js` owns cancellation and checks the latest engine snapshot before each route step. `src/map.js` maintains a cached symbol layer and draws a local 27 × 13 viewport (seven rows on short screens), plus a full-floor pan/zoom dialog. Travel paths remain internal; neither map nor the world renders route lines or destination markers. `routePoints` diagnostics report remaining planned points rather than GPU line vertices.

`src/hud.css` lays out the bottom controls, compact/expanded symbol maps, persistent inventory, and right-hand effect rail. Inventory, effect, stat and journal DOM updates use content signatures. `src/audio.js` owns a gesture-unlocked Web Audio mixer with independent music/effect gains, compression, music ducking, stereo FX, and a short room reverb. Original PCM music beds and synchronized mono tension stems live under `public/audio/`; `scripts/build-audio.mjs` reproducibly authors them from a shared E-minor motif. Only the requested region is fetched/decoded; cache entries trim to its pair after transitions. Crossfades are bounded to four music sources, while FX voices are bounded at 24. Scene-change epochs reject stale loads, suspend stops and disconnects voices/music and clears reverb history, and visibility recovery resumes the intended scene at its saved loop offset. User preferences use `ularn3d.audio.v1`, separately from game saves. Read-only `ularnAudio.metrics()` exposes playback state, region, voices, cache, and threat. Audio failures preserve gameplay and offer an explicit gesture retry. `src/combat-effects.js` owns a six-slot, fixed-buffer pool for casting rings and visible projectile segments. Bridge `ularn:combat` events report accepted casts, actual weapon attempts, and only explored, currently visible projectile segments. Cancelled/failed casts generate no visual or audio feedback. Animation never simulates damage. Bridge `ularn:action` events report successful inventory pickup/consumption and actual door/chest changes; no action audio is inferred from merely opening a prompt. Main derives footsteps, gold pickup, floor transitions, and endings from completed snapshots. Audio noise/variation uses its own generator and never consumes the engine random stream.

`src/icons.js` defines 35 original SVG interface icons on a shared 24-unit grid. Static icon slots mount once; the sound toggle and hero emblem update only when their state changes. Icons inherit control colors, remain hidden from assistive technology, and never intercept pointer input. Buttons retain text labels or explicit accessible names. The site favicon uses the same Ularn sigil. No icon fonts, external icon requests, or additional dependencies are required.

Native engine context buttons and its terminal panels remain available for the complete set of original commands. The bridge namespaces their IDs, replaces the engine's absolute page layout, and disables upstream telemetry and recording services. `common/score-service.js` owns Supabase reads, immutable inserts, and per-run persistent upload keys. Both adapters redirect the upstream score hooks to this service with a 3D/classic edition identifier. Local results are written before online submission; offline endings enqueue instead of returning early. Requests time out after eight seconds, retry transient failures with bounded backoff, and omit credentials/referrers. Repeated inserts ignore the `(edition, game_id)` primary-key conflict instead of updating results. Public clients have SELECT and column-limited INSERT grants under RLS, with no UPDATE/DELETE or client timestamp grants. IP addresses and browser/player identifiers are excluded. Debug runs are not uploaded. The menu and `z` expose the global board, local-records toggle, upload status, and score details. Delegated score links avoid JavaScript URLs; request generations discard stale board/detail responses. The existing replay-verified `scores`/`runs` backend belongs to a different engine version and is preserved separately.

The vendor source has small adapters: `store.js` only advertises replay links when recording is enabled, and `explore.js` rechecks cancellation after awaited approach animations. The latter prevents an interrupted native explorer from taking a queued step after a pause or manual command. Gold pickup now checks the same auto-loot preference as other loot, and spell resolution offers a presentation-only acceptance hook after its rule checks. Small copy edits in `object.js` explicitly identify up/down stairs and dry fountains; `fountain.js` announces that draining leaves no water. Fountain prompts use “wash.” The original draining checks still replace the fountain tile with `ODEADFOUNTAIN`, and the existing floor-state save path persists that object unchanged. Combat, monster AI, stair-transition rules, and progression rules are otherwise unchanged.

`src/terrain-grid.js` instances known floor and wall tiles in 8 × 8 chunks and rebuilds only changed chunks. `src/static-world.js` preserves source tile groups for picking while rendering spatially merged scenery. `src/graphics-utils.js` bakes tint into vertex colors so compatible surfaces share draw calls. Geometries, materials and textures are reused; owned merged geometry and labels are disposed on replacement. Wall cutaways update nearby chunks; foreground buildings use private fading materials.

Rendering uses requestAnimationFrame pacing at 60 FPS while active. Auto starts with Balanced rendering and moves between three tiers after two seconds of sustained overload or ten seconds of active headroom, changing resolution, shadows, lights, bloom and half-resolution ambient occlusion. Manual Balanced/Cinematic preferences persist. Auto and Balanced stop settled gameplay rendering; Cinematic idles at 12 FPS. Background windows suspend frames. Hero movement restores the earlier exponential glide (rate 11), normalized to settle exactly after 280 ms; creatures keep their 100 ms interpolation. Both retarget from the displayed position. Walking phase follows actual displayed distance for continuous alternating feet, with quieter body/arm motion; camera follow retains orbit and zoom, with a view offset derived from the unobscured HUD area. Reduced motion snaps movement and disables decorative motion.

`src/lighting.js` keeps torch identities stable across nearest-distance ties and fades replacements to zero before moving them. Torch variation is source-anchored and limited to 1.2%. Directional shadows snap to light-space texels, use a zoom-sensitive orthographic range with hysteresis, and refresh moving geometry at 30 Hz in lighter tiers or 60 Hz in higher tiers. Floor/normal/roughness maps use mipmaps and anisotropic filtering. Wall caps fit inside their tile instead of overlapping adjacent caps. Wall cutaways interpolate from the displayed hero position and settle exactly, with angular/distance hysteresis; building fades use screen-bound hysteresis and stop writing depth while translucent. Batching preserves shadow/depth flags so flames and ground markers do not create unstable tiny shadows. Cinematic adds an offline SMAA pass before output tone mapping. Repeated damage coalesces a health-only indicator instead of restarting a canvas-wide color filter.

A PMREM environment supplies reflections. Context loss releases GPU registrations, including off-scene cached creature/model/material resources, while preserving CPU artwork. Restoration reuploads resources and regenerates the environment. Read-only `ularnGraphics.metrics()` reports effective quality, resolution, frame/input/update percentiles, chunk rebuilds, routes, save timings and resource counts, plus weapon model, swing phase, arm/weapon pose, trail samples and confirmed impacts. `creatures()` exposes model identity, logical tile, displayed position and facing; `projectTile()` supplies read-only screen coordinates. Spell and fountain lifetimes use wall time.

## Persistence

The autosave key is `ularn3d.expedition.v1`. Saves contain a version, the engine's complete `GameState`, and optional equipped-slot indices, compressed with the bundled LZString library. Equipped-slot metadata distinguishes identical items so the exact wielded/worn objects survive reload; existing version-one saves without this metadata remain readable. Saving only happens between stable turns: never during a blocking callback, animation, or after death. Autosaves coalesce over two seconds, serialize stable state immediately and compress it in `/engine/workers/autosaveWorker.js`. A per-slot queue keeps the latest pending capture. Sequence IDs pair responses with jobs, and an epoch invalidates results superseded by manual saves or endings. Periodic namespaced checkpoint backups use this queue and retain the engine compressed-storage convention. Worker initialization/runtime failure retries stable captures during an idle opportunity. `ularnPersistence.metrics()` exposes capture, worker compression and storage-write timings without write capabilities. Manual and exit saves remain synchronous to avoid losing pending state. The original `S` command is adapted to save without invoking the legacy save-and-die path.

Resume calls the original `loadState` after structural validation, avoiding legacy save deletion. Each start attempt resets monster-template combat values to their originals; both new games and resumes then run the original difficulty calculation exactly once. Saved individual monsters retain their own health and combat values. All original save-slot, backup, checkpoint, and winner-mail keys are redirected to a `ularn3d.legacy.` prefix; periodic checkpoints and endings therefore preserve classic save slots. Preferences and local leaderboard handling remain as before. Save errors dispatch a presentation event immediately. Informational telemetry is disabled; original error/warning diagnostics remain visible in the local browser console. The 3D door shortcut sends the original Open command and its requested direction synchronously; it sends no direction when the original rules reject Open. Enter/Space activate focused interface controls through the browser while other gameplay commands retain their engine mapping. The UI interrupts both its own route timer and the native engine explorer when pausing, opening help, or hiding the page. Input is also gated while a dialog is open or graphics are unavailable. Original local score handling is retained. The menu and `z` command expose the Supabase leaderboard with a local-records toggle, upload status, and visible score details. Recorded replays and the weekly challenge service are not attached to this fork.

## Deployment

`npm run build` produces `dist`; Vercel serves those static files. Public entry points are [browser play](https://ularn-3d.vercel.app/), the [static guide](https://ularn-3d.vercel.app/about/), and the optional [Windows executable](https://ularn-3d.vercel.app/downloads/Ularn.windows.exe). The classic fallback is served directly from `/engine/larn_local.html`. These are real files and directory indexes, so no SPA wildcard rewrite is needed. Source scripts and the original engine license are kept with the project. `package-lock.json` pins dependencies.

The game and guide contain canonical URLs, descriptions, Open Graph/Twitter metadata, and JSON-LD. Their shared social image is `public/social/ularn.png`. `public/robots.txt` points to `public/sitemap.xml`, which lists `/` and `/about/`. `vercel.json` redirects duplicate document/guide URLs to their canonical paths, marks `/engine/` and `/downloads/` responses as non-indexable, and sends attachment/content-type headers for `Ularn.windows.exe`. Downloads require cache revalidation because the published filename is stable across releases.

The Electron host in `desktop/main.cjs` serves `dist/` through `ularn://game/`, with a sandboxed renderer, no Node integration, and a persistent `Ularn` profile. Remote requests are blocked except GET, POST and OPTIONS on `/rest/v1/ularn_scores` at the configured Supabase origin; the CSP permits that origin while the request policy restricts paths and methods. `desktop/protocol.cjs` confines local requests to packaged assets and resolves directory URLs such as `/about/` to their `index.html`. Closing the app saves the last stable turn before flushing storage. Desktop and browser saves have separate storage origins.

`desktop/electron-builder.yml` produces the self-contained Windows x64 portable `Ularn.windows.exe`, plus optional app-folder, ZIP, and installer targets. Its pinned NSIS `1.2.1` bundle includes a native Apple Silicon compiler, so the portable executable can be cross-built without Rosetta. `npm run desktop:package:win:portable` builds the game and executable; `npm run desktop:verify:portable` extracts that executable, verifies all embedded runtime files and game assets against the local build, and writes its SHA-256 sidecar. The Windows GitHub Actions workflow builds and verifies artifacts without publishing the website. See [DESKTOP.md](docs/DESKTOP.md).

The release boundary is explicit: the verified executable and checksum are copied from `release/` to `public/downloads/Ularn.windows.exe` and `public/downloads/SHA256SUMS.txt`. The executable is Git-ignored, so each fresh release environment must rebuild or retrieve it before the website build. Vite then copies both files into `dist/downloads/`. Desktop packaging excludes that directory, preventing recursive executable payloads; `.vercelignore` excludes the separate `release/` working directory.

Production releases use `vercel pull --yes --environment=production`, `vercel build --prod`, and `vercel deploy --prebuilt --prod` after download staging. Before deployment, compare the executable and checksum in `.vercel/output/static/downloads/` with the staged files. The exact commands are in [README.md](README.md#build-and-vercel). This ships the browser game, guide, metadata, and optional desktop download together in one static deployment.

## Validation boundaries

Playwright verifies actual browser input, presentation state, and serialized reloads. Fixtures seed difficult-to-reach scenarios such as demon visibility, death, and quest completion, then exercise the original callbacks. No gameplay cheats or test-only endpoints are included in the UI. Automated verification reduces regression risk; it cannot prove that a large random roguelike has no defects.

Site checks cover the static guide, metadata, sitemap, and download links. Desktop tests cover local asset routing, traversal rejection, renderer isolation, first-launch storage creation, and saving through a complete Electron restart. Portable extraction verification proves the runtime payload is self-contained; macOS tests do not execute the Windows binary.
