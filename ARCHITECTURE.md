# Architecture

## Runtime

The game is a static Vite application with an optional offline Electron desktop host. Three.js renders the world with a perspective camera, shadows, fog, procedural meshes, and pointer controls. There is no application backend.

The public website keeps a marketing home at `/`, browser play at `/play/`, and a field guide at `/about/` that also holds Larn / Ultra-Larn history (`/about/#history`). Legacy `/credits` URLs redirect there. Static pages under `public/` are copied into the build; `vite.config.js` uses multipage mode (home + play entries) and directory-index middleware so development and preview match production URLs. `public/site-runtime.js` identifies the browser or `ularn:` desktop host and hides web-only download controls inside the desktop application.

`public/engine/` contains the original JavaScript Larn/Ularn source and assets. `scripts/build-engine.mjs` concatenates its classic scripts in upstream load order, includes the shared score service, then appends `src/bridge.js`, producing `public/engine/game.js`. It also generates public JS/JSON score configuration from `scoreboard.config.json` and optional Vite environment overrides, rejecting privileged keys. Both entry points load that configuration before initializing the service. The Vite build copies this bundle and other public assets into `dist`.

## Authority and state

The original engine owns level generation, player attributes, items, monsters, movement, turns, combat, spells, shops, traps, time limits, and endings. The 3D UI sends ordinary engine commands through `window.ularn.key()`. It does not independently simulate gameplay. The bridge applies one explicit balance adjustment for solo 3D play (disabled in online rooms and deterministic replay sessions): new lemming placements are capped at four per floor, movement and melee attacks cannot spawn offspring, and melee dispatches a lemming through the normal damage/death/loot/experience path in one attempt. The movement adapter then advances into that cleared square within the same engine action, preserving normal terrain/loot handling and one turn per step. It disables the extra advance while confused or time-stopped. Harmless lemmings cannot set attack-interruption flags or suppress nearby interactions, rest or native exploration. New cave floors seed a rodent when the ordinary population contains none. The random-monster adapter checks for arrivals every 24 actual expedition turns: it refills an empty cave or uses a 60% chance for an additional arrival, still under the cap. Placement prefers empty floor 3–7 cells from the hero and falls back to more distant empty floor. These additions do not run in town/volcano, under time stop, after endings or when the species is genocided. The saved player turn count supplies the cadence, so no new save fields or wall-clock timers are needed. A weak set distinguishes existing creatures being relocated from new placements; restored swarms above the cap are preserved. The vendored classic scripts and classic rules remain intact.

The bridge exposes `start`, `snapshot`, `key`, `openToward`, `save`, `hasSave`, `interruptTravel`, and `setAutoLoot`. Snapshot adds inventory slots/equipment, actual effect timers, map glyphs, weapon families, and weakly held monster presentation identities/facing. Visible creatures include a `harmless` capability derived from the actual engine species; a mimic presented as a lemming stays hostile. The navigation helper defaults to blocking creatures without this capability. Known, unmasked staircase tiles also receive direction and blocked-state metadata derived from the existing `stairs.js` dead-end conditions; blocked stair names append `(dead end)`. Snapshot construction filters unexplored tiles, hidden traps, invisible monsters, and blindness using the engine's knowledge flags and visibility checks. The presentation never treats its meshes as authoritative collision data.

`src/world.js` renders known tiles and follows the player. `src/materials.js` caches procedural surface maps and materials. `src/models.js` builds the player, buildings, creature families, terrain objects, and items from local procedural geometry. `src/main.js` owns HUD updates, input, contextual-menu layout, known-tile pathfinding, minimap, camera controls, sound, and start/pause/help flows. Clicking a staircase underfoot dispatches the original `<` or `>` command according to its tile identity. Stair models display direction-specific steps or rubble and a cross for intentional dead ends. The usable Volcano 1 exit is a separate shaft tile labeled `SURFACE SHAFT`; its behavior is not inferred from the blocked staircase rules.

`src/monster-art.js` caches artwork by exact species. Most species use the original bundled sprites, including Ularn and revealed-monster variants. `src/creature-models.js` replaces five species with shared procedural meshes selected by id: lemming (1), gnome (2), jackal (4), floating eye (12), and red dragon (56). Those meshes keep the engine identity, face by yaw, and report `presentation: "model"` in graphics diagnostics. Every other species stays a camera-facing sprite with a heading marker. The lemming illustration in `public/art/monsters/lemming.png` remains the hover-card picture; its prompt is in [docs/art/lemming.prompt.md](docs/art/lemming.prompt.md). The classic `public/engine/img/m1u.png` sprite is unchanged. Ambient wall rats stay the side-view billboard from `src/ambient-rats.js`. Monster groups retain identity across tile movement.

`src/item-art.js` caches presentation artwork for floor loot under `public/art/items/` (97 unique sprites). Generation provenance is recorded in [docs/art/items.prompt.md](docs/art/items.prompt.md). Covered categories are weapons, armor, rings, belt of striking, potions (full table by `arg`), scrolls (full table by `arg`), books, cookies, artifacts, gems, and gold piles. The bridge snapshot exposes item `arg` so potion/scroll variants resolve correctly. Camera-facing planes mirror left/right as the overhead camera orbits. Engine item identities, stats, spawn rules, and classic `public/engine/img/o{id}.png` tiles remain unchanged; unlisted tiles still use procedural meshes from `itemModel`.

`src/creatures.js` defines an exact-ID registry for all 66 Ularn species, including the loot goblin. Family rigs use cached, shared geometry with species-specific proportions and details. Authored resting rotations survive walking, wing and tail animation and reduced-motion resets. Mirrored wing polygons are triangulated before batching to preserve winding and lighting. Actor groups preserve bridge identity across movement, rotate toward engine facing, and animate their joints without simulating turns. Mimics and hidden creatures use only the bridge's already-filtered presentation identity. Class-specific heroes and equipment families are built in `src/models.js`. Weapons use cached, merged templates, including six detailed sword designs alongside the current thin dagger; changing between sword IDs updates the held model even within the same family. A shoulder/hand hierarchy keeps the blade attached to the animated arm. `src/hero-animation.js` runs one retargetable action with 55 ms wind-up, 105 ms contact and 330 ms settling, alternating closely spaced slashes. An eight-sample fixed ribbon and ten-point impact buffer supply bounded feedback. Only resolved combat events start actions; waiting does not simulate an attack. Misses and unseen targets produce no impact spark. Pause, hiding, context loss, equipment changes and floor transitions reset the pose. Reduced motion skips both swing and transient feedback. Contact audio uses the same 105 ms timing without delaying engine actions. Legacy sprites and the former lemming illustration remain bundled reference/classic assets.

`src/navigation.js` owns known-tile shortest-route planning and the cancellable held-input timer. Route planning, step revalidation and visible-danger checks share the same hostile-creature predicate, so harmless lemmings remain traversable while enemies and known hazards still block travel. The first directional action is immediate, the initial repeat delay is 220 ms, and subsequent steps run every 140 ms. A delayed timer issues one action without catch-up. `src/main.js` owns cancellation and checks the latest engine snapshot before each route step. `src/map.js` maintains a cached symbol layer and draws a local 27 × 13 viewport (seven rows on short screens), plus a full-floor pan/zoom dialog. Travel paths remain internal; neither map nor the world renders route lines or destination markers. `routePoints` diagnostics report remaining planned points rather than GPU line vertices.

`src/hud.css` lays out the bottom controls, compact/expanded symbol maps, persistent inventory, and right-hand effect rail. Inventory, effect, stat and journal DOM updates use content signatures. `src/audio.js` owns a gesture-unlocked Web Audio mixer with independent music/effect gains, compression, music ducking, stereo FX, and a short room reverb. Original PCM music beds and synchronized mono tension stems live under `public/audio/`; `scripts/build-audio.mjs` reproducibly authors them from a shared E-minor motif. Only the requested region is fetched/decoded; cache entries trim to its pair after transitions. Crossfades are bounded to four music sources, while FX voices are bounded at 24. Scene-change epochs reject stale loads, suspend stops and disconnects voices/music and clears reverb history, and visibility recovery resumes the intended scene at its saved loop offset. User preferences use `ularn3d.audio.v1`, separately from game saves. Read-only `ularnAudio.metrics()` exposes playback state, region, voices, cache, and threat. Audio failures preserve gameplay and offer an explicit gesture retry. `src/combat-effects.js` owns a six-slot, fixed-buffer pool for casting rings and visible projectile segments. Bridge `ularn:combat` events report accepted casts, actual weapon attempts, and only explored, currently visible projectile segments. Cancelled/failed casts generate no visual or audio feedback. Animation never simulates damage. Bridge `ularn:action` events report successful inventory pickup/consumption and actual door/chest changes; no action audio is inferred from merely opening a prompt. Main derives gold pickup, floor transitions, and endings from completed snapshots. Adjacent-tile player movement emits a renderer footfall at the plant (or immediately under reduced motion), with pending footfalls discarded on menus, reset and visibility/context loss. Footsteps use two short dry voices with private pitch/level variation and an 85 ms cooldown. Audio noise/variation uses its own generator and never consumes the engine random stream.

`src/icons.js` defines 35 original SVG interface icons on a shared 24-unit grid. Static icon slots mount once; the sound toggle and hero emblem update only when their state changes. Icons inherit control colors, remain hidden from assistive technology, and never intercept pointer input. Buttons retain text labels or explicit accessible names. The site favicon uses the same Ularn sigil. No icon fonts, external icon requests, or additional dependencies are required.

Native engine context buttons and its terminal panels remain available for the complete set of original commands. The bridge namespaces their IDs, replaces the engine's absolute page layout, and disables upstream telemetry and recording services. `common/score-service.js` owns Supabase reads, immutable inserts, and per-run persistent upload keys. Both adapters redirect the upstream score hooks to this service with a 3D/classic edition identifier. Local results are written before online submission; offline endings enqueue instead of returning early. Requests time out after eight seconds, retry transient failures with bounded backoff, and omit credentials/referrers. Repeated inserts ignore the `(edition, game_id)` primary-key conflict instead of updating results. Public clients have SELECT and column-limited INSERT grants under RLS, with no UPDATE/DELETE or client timestamp grants. IP addresses and browser/player identifiers are excluded. Debug runs are not uploaded. The menu and `z` expose the global board, local-records toggle, upload status, and score details. Delegated score links avoid JavaScript URLs; request generations discard stale board/detail responses. Solo/classic results use `ularn_scores`; online rooms retain the authenticated replay-verified `runs`/`scores` pipeline. Solo-only balance adapters are disabled while `PARTY_ON` is true, preserving deterministic room inputs and server replay rules.

The vendor source has small adapters: `store.js` only advertises replay links when recording is enabled, and `explore.js` rechecks cancellation after awaited approach animations. The latter prevents an interrupted native explorer from taking a queued step after a pause or manual command. Gold is always collected; auto-loot only applies to other items. Spell resolution offers a presentation-only acceptance hook after its rule checks. Small copy edits in `object.js` explicitly identify up/down stairs and dry fountains; `fountain.js` announces that draining leaves no water. Fountain prompts use “wash.” The original draining checks still replace the fountain tile with `ODEADFOUNTAIN`, and the existing floor-state save path persists that object unchanged. Combat, monster AI, stair-transition rules, and progression rules are otherwise unchanged.

Known floor and wall tiles are GPU-instanced from 12-triangle boxes. Empty floors and walls do not spawn a scene-graph Group; only items, landmarks, and creatures do. `src/ambient-rats.js` keeps a fixed pool of two decorative wall-top rats outside actors/props so pick, combat, and inventory never see them. Size, tint, facing, and pose come from the tile, and the pair stays several tiles apart. Town skips them, and only near-camera scurries briefly keep the frame loop awake. Static terrain and buildings in both the title scene and gameplay are merged by material; reusable model geometries are shared and kept to low segment counts (boxes instead of rounded boxes, 80-triangle orbs, 128-triangle rings). Distant title and town terrain does not cast shadows, and the dungeon footprint slab does not either. Replaced merged geometry and landmark textures are disposed when levels change. Shadows update when the scene or wall layout changes, not on every camera-side cutaway, and Balanced does not refresh the shadow map while the hero walks. Camera-side cutaway only lowers the wall column between the camera and the hero, and town plaza walls stay full height so walking past them does not open a hole. Balanced rendering skips the PMREM environment, MSAA, extra torch point lights, and the hero point light (town and dungeon); uses Lambert floors/walls without bump maps; keeps wall tiles from casting shadows; caps the pixel ratio below native DPR; skips rebuilding unchanged floor/wall/prop structure on a walk step; never allocates the bloom composer; and raises cave ambient, sun, and fill so a dungeon stays readable without those point lights. Cinematic restores richer materials, full contact shadows that follow the hero, a half-resolution bloom pass, and output color conversion. The marketing home preview always runs Balanced so a leftover Cinematic preference cannot bloom-lag the landing page. On context loss, the renderer releases GPU resource registrations while retaining CPU-side geometry and materials. Restoration reuploads that artwork and regenerates the reflection environment when cinematic. This prevents stale-handle deletion errors during later WebKit level changes, quality changes, and resizes. Read-only `ularnGraphics.metrics()` reports rendering, frame limits, idle state, sprite/effect pools, active lights, floor/wall instance counts, prop groups, shadow update counts, floor material type, bloom/composer allocation, lighting intensities, and GPU resource counts for diagnostics. The WebGL renderer requests a high-performance GPU. Camera orbit, zoom, and walk follow `requestAnimationFrame` without an extra timeout throttle so panning stays vsync-smooth; Balanced still stops drawing once the scene settles, and Cinematic idles at 12 FPS. Hidden windows stop frame scheduling. Floor-loot sprites flood-fill pale generated cards out of their alpha so items do not sit on a white plate. Transient spell and fountain lifetimes use wall time to expire correctly even on slow hardware. Per-frame work faces only billboard sprites and draining fountains rather than walking every tile group. The expanded minimap shows the full floor; the compact map follows the hero; it paints known tiles instead of filling every unexplored cell, and walking only rewrites the old and new player cells when the charted content is unchanged.

Merged rendering uses `ChunkedTerrainMesh` to preserve the existing matrix/color, wall-cutaway, terrain-tint and raycast interfaces while uploading changed 8×8 chunks. `StaticTiles` batches compatible scenery while preserving source groups for picking and item identity. Auto quality adjusts its resolution after sustained overload/headroom; Cinematic adds SSAO and SMAA. The current north camera, 140 ms collision-aware steps with restrained body motion and articulated knees/ankles, flat mapped caves, loot artwork, ambient rats, and cooperation aura remain. Town cinematic lights use stable fading assignments and snapped shadow texels.

## Persistence

The autosave key is `ularn3d.expedition.v1`. Saves contain a version, the engine's complete `GameState`, and optional equipped-slot indices, compressed with the bundled LZString library. Equipped-slot metadata distinguishes identical items so the exact wielded/worn objects survive reload; existing version-one saves without this metadata remain readable. Saving only happens between stable turns: never during a blocking callback, animation, or after death. Walking marks the in-memory dirty flag and schedules a coalesced two-second worker capture. Compression runs in the worker, guarded by capture generations; explicit Save, Save & Exit, tab hide, page unload, and graphics loss save synchronously and invalidate older worker jobs. Manual and exit saves remain synchronous to avoid losing pending state. The original `S` command is adapted to save without invoking the legacy save-and-die path. The 3D journal keeps a deep scrollable history soft-capped at `LOG_JOURNAL_CAP` (2000) so LOG, snapshot log views, and journal DOM cannot grow without bound on very long expeditions; classic terminal display still shows the last `LOG_SIZE` lines. Snapshot reuses the log array between paints when unchanged, and `world.update` trusts bridge `structureRev`/`actorRev` so quiet known-floor walks skip re-hashing every tile.

Resume calls the original `loadState` after structural validation, avoiding legacy save deletion. Each start attempt resets monster-template combat values to their originals; both new games and resumes then run the original difficulty calculation exactly once. Saved individual monsters retain their own health and combat values. All original save-slot, backup, checkpoint, and winner-mail keys are redirected to a `ularn3d.legacy.` prefix; periodic checkpoints and endings therefore preserve classic save slots. Preferences and local leaderboard handling remain as before. Save errors dispatch a presentation event immediately. Informational telemetry is disabled; original error/warning diagnostics remain visible in the local browser console. The 3D door shortcut sends the original Open command and its requested direction synchronously; it sends no direction when the original rules reject Open. Enter/Space activate focused interface controls through the browser while other gameplay commands retain their engine mapping. The UI interrupts both its own route timer and the native engine explorer when pausing, opening help, or hiding the page. Input is also gated while a dialog is open or graphics are unavailable. Original local score handling is retained. The menu and `z` command expose the Supabase leaderboard with a local-records toggle, upload status, and visible score details. Recorded replays and the weekly challenge service are not attached to this fork.

## Deployment

`npm run build` produces `dist`; Vercel serves those static files. Public entry points are the [home page](https://ularn-3d.vercel.app/), [browser play](https://ularn-3d.vercel.app/play/), the [field guide and history](https://ularn-3d.vercel.app/about/), [What’s New](https://ularn-3d.vercel.app/changelog/), and the optional [Windows executable](https://ularn-3d.vercel.app/downloads/Ularn.windows.exe). The classic fallback is served directly from `/engine/larn_local.html`. These are real files and directory indexes, so no SPA wildcard rewrite is needed. Source scripts and the original engine license are kept with the project. `package-lock.json` pins dependencies. Production deploys for `helloivanco/ularn3d` target the Vercel project that serves `ularn-3d.vercel.app`.

The game and guide contain canonical URLs, descriptions, Open Graph/Twitter metadata, and JSON-LD. Their shared social image is `public/social/ularn.png`. `public/robots.txt` points to `public/sitemap.xml`, which lists `/`, `/play/`, `/about/`, and `/changelog/`. Curated player notes live in root `CHANGELOG.md` and the marketing What’s New page; [GitHub Releases](https://github.com/helloivanco/ularn3d/releases) hold the full artifact history. `vercel.json` redirects duplicate document/guide URLs to their canonical paths, sends legacy `/credits` URLs to `/about/#history`, marks `/engine/` and `/downloads/` responses as non-indexable, and sends attachment/content-type headers for `Ularn.windows.exe`. The published URL path is stable across releases; Vercel redirects it to the GitHub Release asset `Ularn-${version}.windows.exe` for the current `package.json` version so Git deploys cannot omit the binary. The play page, field-guide footer, JSON-LD, and Electron package display that same version. Each product release runs `npm version` so those surfaces cannot keep a previous number.

The Electron host in `desktop/main.cjs` serves `dist/` through `ularn://game/`, with a sandboxed renderer, no Node integration, and a persistent `Ularn` profile. Remote requests are blocked except GET, POST and OPTIONS on `/rest/v1/ularn_scores` at the configured Supabase origin; the CSP permits that origin while the request policy restricts paths and methods. `desktop/protocol.cjs` confines local requests to packaged assets and resolves directory URLs such as `/about/` to their `index.html`. Closing the app saves the last stable turn before flushing storage. Desktop and browser saves have separate storage origins.

`desktop/electron-builder.yml` produces the self-contained Windows x64 portable `Ularn.windows.exe`, plus optional app-folder, ZIP, and installer targets. Its pinned NSIS `1.2.1` bundle includes a native Apple Silicon compiler, so the portable executable can be cross-built without Rosetta. `npm run desktop:package:win:portable` builds the game and executable; `npm run desktop:verify:portable` extracts that executable, verifies all embedded runtime files and game assets against the local build, and writes its SHA-256 sidecar. The Windows GitHub Actions workflow builds and verifies artifacts, and a push to `main` publishes the versioned portable file as a GitHub Release. See [DESKTOP.md](docs/DESKTOP.md).

The executable is Git-ignored, so a source-only Vercel Git build cannot embed it. The site keeps `/downloads/Ularn.windows.exe` and redirects that path (and the checksum) to the GitHub Release for the current `package.json` version. Desktop packaging still excludes `dist/downloads/`, preventing recursive executable payloads; `.vercelignore` excludes the separate `release/` working directory.

Optional local prebuilt deploys can still stage a verified executable under `public/downloads/` before `vercel build --prod`. The exact commands are in [README.md](README.md#build-and-vercel). GitHub Releases are the hosted download used by production.

## Validation boundaries

Playwright verifies actual browser input, presentation state, and serialized reloads. Fixtures seed difficult-to-reach scenarios such as demon visibility, death, and quest completion, then exercise the original callbacks. No gameplay cheats or test-only endpoints are included in the UI. Automated verification reduces regression risk; it cannot prove that a large random roguelike has no defects.

Site checks cover the static guide, metadata, sitemap, and download links. Desktop tests cover local asset routing, traversal rejection, renderer isolation, first-launch storage creation, and saving through a complete Electron restart. Portable extraction verification proves the runtime payload is self-contained; macOS tests do not execute the Windows binary.

Seeded deterministic replay sessions retain the native rules and RNG stream; local solo lemming adapters apply only to ordinary unseeded 3D expeditions.
