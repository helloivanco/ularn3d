# Architecture

## Runtime

The game is a static Vite application with an optional offline Electron desktop host. Three.js renders the world with a perspective camera, shadows, fog, procedural meshes, and pointer controls. There is no custom game server. Supabase authenticates room members and orders multiplayer actions.

The public website keeps a marketing home at `/`, browser play at `/play/`, and a field guide at `/about/` that also holds Larn / Ultra-Larn history (`/about/#history`). Legacy `/credits` URLs redirect there. Static pages under `public/` are copied into the build; their gameplay screenshots, social card and calling portraits (`public/art/heroes/`) come from `npm run site:capture` (`scripts/capture-site.mjs`), which stages each scene through the engine globals against the dev server and renders it in Cinematic; `vite.config.js` uses multipage mode (home + play entries) and directory-index middleware so development and preview match production URLs. `public/site-runtime.js` identifies the browser or `ularn:` desktop host and hides web-only download controls inside the desktop application.

`public/engine/` contains the original JavaScript Larn/Ularn source and assets. `scripts/build-engine.mjs` concatenates its classic scripts in upstream load order, includes the shared score service, then appends `src/bridge.js`, producing `public/engine/game.js`. It also generates public JS/JSON score configuration from `scoreboard.config.json` and optional Vite environment overrides, rejecting privileged keys. Both entry points load that configuration before initializing the service. The Vite build copies this bundle and other public assets into `dist`.

## Authority and state

The original engine owns level generation, player attributes, items, monsters, movement, turns, combat, spells, shops, traps, time limits, and endings. The 3D UI sends ordinary engine commands through `window.ularn.key()`. It does not independently simulate gameplay. Solo 3D uses the engine's one-lemming floor cap and classic stocking tiles. It does not add a second lemming population or a 24-turn refill. Melee dispatches a lemming through the normal damage/death/loot/experience path in one attempt, and that bypass skips the lemming's post-attack birth. The movement adapter then advances into that cleared square within the same engine action, preserving normal terrain/loot handling and one turn per step. It disables the extra advance while confused or time-stopped. Harmless lemmings cannot set attack-interruption flags or suppress nearby interactions, rest or native exploration. A saved swarm is thinned to one on Continue. Capital direction letters and Shift run until blocked, and each open step spends a turn the way Ularn's `regen()` does inside `run()`. Solo monster turns stay on the classic window. The vendored classic scripts and classic rules remain intact.

The bridge exposes `start`, `snapshot`, `key`, `openToward`, `usePack`, `save`, `hasSave`, `interruptTravel`, and `setAutoLoot`. `usePack(command, letter)` serves the pinned inventory: clicking an item opens a menu of the classic commands it accepts (snapshot `uses`: quaff, read, eat, wield, wear, then drop), and a choice runs `usePackItem` in `party.js`, which presses the command and then the item's letter only while that command is asking for one. Each command first takes a matching item at the hero's feet, so standing on one refuses with a journal line instead. Rooms send the same choice as a `use:<command>:<letter>` input and replay it through `usePackItem`, as they do `open:`. Snapshot adds inventory slots/equipment, actual effect timers, map glyphs, weapon families, and weakly held monster presentation identities/facing. Visible creatures include a `harmless` capability derived from the actual engine species; a mimic presented as a lemming stays hostile. The navigation helper defaults to blocking creatures without this capability. Known, unmasked staircase tiles also receive direction and blocked-state metadata derived from the existing `stairs.js` dead-end conditions; blocked stair names append `(dead end)`. Snapshot construction filters unexplored tiles, hidden traps, invisible monsters, and blindness using the engine's knowledge flags and visibility checks. The presentation never treats its meshes as authoritative collision data.

`src/world.js` renders known tiles and follows the player. `src/materials.js` paints and caches the procedural terrain family at 512 texels per tile (flagstone floors, wall courses, grass, slate roofs and plank wood; see [docs/art/terrain.md](docs/art/terrain.md)) and their materials. Instanced floor tiles turn and mirror their maps per tile from a position hash, so one stone layout never repeats across a room; walls and caps stay level. `src/models.js` builds the player, buildings, creature families, terrain objects, and items from local procedural geometry. `src/main.js` owns HUD updates, input, contextual-menu layout, known-tile pathfinding, minimap, camera controls, sound, and start/pause/help flows. Clicking a staircase underfoot dispatches the original `<` or `>` command according to its tile identity. Stair models display direction-specific steps or rubble and a cross for intentional dead ends. Stairs going up are solid steps with posted rails; stairs going down are a well cut into the floor (`opensFloor` drops that tile's floor slab), with steps darkening toward the bottom. Every stair part rests on a surface, including the flat up/down chevrons. Every Ularn trap has its own silhouette, recorded as `trapKind`: pit, dart (including the hidden variant), arrow plate, wooden trapdoor, violet teleport rune circle and the two express elevators. The jewel-encrusted throne shows four gems that become empty sockets on the engine's "massive throne". The mirror uses a painted, unlit reflection, because a metal plane renders black without an environment map. The sphere of annihilation is a lightless void with violet halos. Dealer McDope's five wares and the amulet of life preservation have their own models instead of the generic gem. A known cure-dianthroritis potion stands in a soft additive glow on the floor. The usable Volcano 1 exit is a separate shaft tile labeled `SURFACE SHAFT`; its behavior is not inferred from the blocked staircase rules.

`src/hero-skin.js` dresses the hero and the undead (zombie, wraith, vampire) in rigged KayKit bodies (CC0; see [docs/art/models.md](docs/art/models.md)). The procedural hero and creatures stay the logical rigs: their poses, facing, weapon pivot and sword trail run hidden, and only the weapon and lantern move to the rigged `handslot` bones. One `AnimationMixer` per body blends an idle/walk/run base, paced from the planned glide speed, with one action on top: an attack by weapon style, a cast, a hit from `hitMonster` or `heroHurt`, an attack from `lungeMonster`, and death from `collapse`. Bodies advance on the action clock, so hit-stop holds them, and blend weights are set by hand so a finished action hands back to the current base. The feedback system's flashes and corpses carry the rigged bodies; a corpse frees its skeleton when it finishes. The title starts fetching the bodies it can start (the chosen calling, a saved run, the weekly calling), so play usually opens dressed. Until a body arrives the hero stays hidden, so the procedural body never flashes in; it shows only if the load fails or takes longer than 4 s.

`src/set-dressing.js` places instanced KayKit props in cave corners and dead ends, and mounted torches with an additive glow on a share of the lamp walls. Placement is a pure function of the known walls, never on item tiles or under a torch, and uses nothing that could pass for loot. Torches hide while their wall column is cut away. Cinematic adds a soft shade where floor meets wall and breathing flames. Chests use the pack chest once it has loaded. In town it plans lamp posts along the paths (which join the town lamps), barrels and crates beside shop fronts, and procedural tufts, wildflowers, stones and bushes on the lawns, never on a path or within a tile of a building. Cinematic grows a denser meadow of tufts in noise-shaped patches on the same lawns, and tufts, flowers and bushes sway in a breeze: their own `MeshStandardMaterial` bends each piece from its base toward its tip along one world direction, with slow gusts rolling across the town and a quicker ripple, so neighbours lean together. In Cinematic caves the four wall torches nearest the hero take the torch-light slots that light the town; each slot's light hangs 0.4 tiles out from its flame (redder on volcano floors) and wavers with a slow swell and a quicker shiver. On each level change, `warmShaders()` compiles and links the effect programs that first draw mid-fight (sword trail, sparks, hurt burst, spell shapes, level-up column), so the first blow does not stall; `ularnGraphics.programs()` lists compiled programs for tests.

Every one of the 66 species is presented by its procedural rig from `src/creatures.js` (below), tried first in `syncMonsterActors`. `src/creature-models.js` (five shared meshes) and `src/monster-art.js` (sprites cached by exact species) remain as fallbacks and for diagnostics; rigs and models face by yaw and report `presentation: "model"`. The lemming illustration in `public/art/monsters/lemming.png` remains the hover-card picture; its prompt is in [docs/art/lemming.prompt.md](docs/art/lemming.prompt.md). The classic `public/engine/img/m1u.png` sprite is unchanged. Ambient wall rats are a rigged model of their own (below). Monster groups retain identity across tile movement.

`src/item-art.js` caches presentation artwork for floor loot under `public/art/items/` (97 unique sprites). Generation provenance is recorded in [docs/art/items.prompt.md](docs/art/items.prompt.md). Covered categories are weapons, armor, rings, belt of striking, potions (full table by `arg`), scrolls (full table by `arg`), books, cookies, artifacts, gems, and gold piles. The bridge snapshot exposes item `arg` so potion/scroll variants resolve correctly. Camera-facing planes mirror left/right as the overhead camera orbits. Engine item identities, stats, spawn rules, and classic `public/engine/img/o{id}.png` tiles remain unchanged; unlisted tiles still use procedural meshes from `itemModel`. The generated PNGs carry a baked pale card or fake checkerboard, which the loader strips once per texture. The strip is a 4-connected flood from the edges that only takes neutral pale pixels, so it cannot leak through a one-pixel diagonal outline into white facets, steel blades or tinted glass. It then clears enclosed two-tone checker regions, such as ring holes, that are ringed mostly by dark or saturated item pixels. Each loot sprite stands on a `lootShade` (a solid-core, feathered contact shade) like the discs under creatures. Pack rows ask `itemArtImage` with a callback, which fetches art not yet seen on the floor (starting gear, a continued pack, purchases) and draws it into the row when it loads.

`src/creatures.js` defines an exact-ID registry for all 66 Ularn species, including the loot goblin. Family rigs use cached, shared geometry with species-specific proportions and details. Authored resting rotations survive walking, wing and tail animation and reduced-motion resets. Mirrored wing polygons are triangulated before batching to preserve winding and lighting. Actor groups preserve bridge identity across movement, rotate toward engine facing, and animate their joints without simulating turns. Mimics and hidden creatures use only the bridge's already-filtered presentation identity. Class-specific heroes and equipment families are built in `src/models.js`. Weapons use cached, merged templates, including six detailed sword designs alongside the current thin dagger; changing between sword IDs updates the held model even within the same family. A shoulder/hand hierarchy keeps the blade attached to the animated arm. `src/hero-animation.js` runs one retargetable action with 55 ms wind-up, 105 ms contact and 330 ms settling, alternating closely spaced slashes. An eight-sample fixed ribbon and ten-point impact buffer supply bounded feedback. Only resolved combat events start actions; waiting does not simulate an attack. Misses and unseen targets produce no impact spark. Pause, hiding, context loss, equipment changes and floor transitions reset the pose. Reduced motion skips both swing and transient feedback. Contact audio uses the same 105 ms timing without delaying engine actions. Legacy sprites and the former lemming illustration remain bundled reference/classic assets.

`src/navigation.js` owns known-tile shortest-route planning and the cancellable held-input timer. Route planning, step revalidation and visible-danger checks share the same hostile-creature predicate, so harmless lemmings remain traversable while enemies and known hazards still block travel. The first directional action is immediate, the initial repeat delay is 220 ms, and subsequent steps run every 140 ms on an ideal timeline that absorbs engine time. A delayed timer issues one action without catch-up and restarts the timeline. The timer reports when the next step is due; `main.js` forwards that to `world.expectNextStep()` while the next known tile is open, and to `world.endRun()` on release, a blocked tile, or `stopTravel()`. Click travel reports its next step the same way. These hints only shape presentation: the renderer's `StepGlide` (`src/hero-motion.js`) carries speed across tiles during a run and eases out when it ends. They never send or delay an engine action. `src/main.js` owns cancellation and checks the latest engine snapshot before each route step. `src/map.js` maintains a cached symbol layer and draws a local 27 × 13 viewport (seven rows on short screens), plus a full-floor pan/zoom dialog. Travel paths remain internal; neither map nor the world renders route lines or destination markers. `routePoints` diagnostics report remaining planned points rather than GPU line vertices.

`src/hud.css` lays out the bottom controls, compact/expanded symbol maps, persistent inventory, and right-hand effect rail. Inventory, effect, stat and journal DOM updates use content signatures. `src/audio.js` owns a gesture-unlocked Web Audio mixer with independent music/effect gains, compression, music ducking, stereo FX, and a short room reverb. An original orchestral score lives under `public/audio/` as lossless FLAC. Each region (town, caves, deep caves for floors 8–15, volcano) has a stereo bed and a two-channel stem, whose channels are the "stir" and "fray" intensity layers; one stinger sprite holds the level-up, descent, cure, death and victory cues. `scripts/build-audio.mjs` composes and renders all of it reproducibly from `scripts/audio/` (score, voice-leading, instrument models, hall, BS.1770 mastering and a dependency-free FLAC encoder). `src/audio-score.js` maps levels to regions and holds the stinger slots for both the build and the runtime. Only the requested region is fetched/decoded; cache entries trim to its pair after transitions. The stem's layers split by channel from a single source, so crossfades stay bounded to four music sources, while FX voices (stingers included) are bounded at 24. Scene-change epochs reject stale loads, suspend stops and disconnects voices/music and clears reverb history, and visibility recovery resumes the intended scene at its saved loop offset. User preferences use `ularn3d.audio.v1`, separately from game saves. Read-only `ularnAudio.metrics()` exposes playback state, region, voices, cache, threat, layer levels and stinger readiness. Audio failures preserve gameplay and offer an explicit gesture retry. `src/combat-effects.js` owns a six-slot, fixed-buffer pool for casting rings and visible projectile segments. Bridge `ularn:combat` events report accepted casts, actual weapon attempts, and only explored, currently visible projectile segments. Cancelled/failed casts generate no visual or audio feedback. Animation never simulates damage. Bridge `ularn:action` events report successful inventory pickup/consumption, actual door/chest changes, and fountain, altar and throne actions the engine performs; no action audio is inferred from merely opening a prompt. Main derives gold pickup, floor transitions, and endings from completed snapshots. Adjacent-tile player movement emits a renderer footfall at the plant (or immediately under reduced motion), with pending footfalls discarded on menus, reset and visibility/context loss. Footsteps use two short dry voices with private pitch/level variation and an 85 ms cooldown. Audio noise/variation uses its own generator and never consumes the engine random stream.

`src/icons.js` defines 43 original SVG interface icons, including the feat and notice emblems, on a shared 24-unit grid. Static icon slots mount once; the sound toggle and hero emblem update only when their state changes. Icons inherit control colors, remain hidden from assistive technology, and never intercept pointer input. Buttons retain text labels or explicit accessible names. The site favicon uses the same Ularn sigil. No icon fonts, external icon requests, or additional dependencies are required.

Native engine context buttons and its terminal panels remain available for the complete set of original commands. The bridge namespaces their IDs, replaces the engine's absolute page layout, and disables upstream telemetry and recording services. `common/score-service.js` owns Supabase reads, immutable inserts, and per-run persistent upload keys. Both adapters redirect the upstream score hooks to this service with a 3D/classic edition identifier. Local results are written before online submission; offline endings enqueue instead of returning early. Requests time out after eight seconds, retry transient failures with bounded backoff, and omit credentials/referrers. Repeated inserts ignore the `(edition, game_id)` primary-key conflict instead of updating results. A queued row the service refuses as invalid (400, 409, 413 or 422) moves to a `ularn.global.rejected.v1.` key so it cannot block later uploads. Public clients have SELECT and column-limited INSERT grants under RLS, with no UPDATE/DELETE or client timestamp grants. IP addresses and browser/player identifiers are excluded. Debug runs are not uploaded. The menu and `z` expose the global board, local-records toggle, upload status, and score details. Delegated score links avoid JavaScript URLs; request generations discard stale board/detail responses. Solo/classic results use `ularn_scores`. When a room's expedition ends, each player's browser also writes its own adventurer there (name, gold, fate recorded when it fell) under the game ID `<run id>-<slot>`, so reloads cannot add a second row and runs too long for the verifier still reach the board. Online rooms additionally keep the authenticated replay-verified `runs`/`scores` pipeline, shown as the Verified co-op tab. Solo-only balance adapters are disabled while `PARTY_ON` is true, preserving deterministic room inputs and server replay rules.

The vendor source has small adapters: `store.js` only advertises replay links when recording is enabled, and `explore.js` rechecks cancellation after awaited approach animations. The latter prevents an interrupted native explorer from taking a queued step after a pause or manual command. Gold is always collected; auto-loot only applies to other items. Solo starts the engine's own auto explore (`X`, also the Explore action), travel to an object (`G`) and travel to stairs (`{`/`}`) switched on unless the player saved a choice in Options; away from stairs, `>` and `<` become that stairs travel when the matching stairs are already seen. Rooms force all three off and the UI never sends those keys, because the explorer takes many private steps that other browsers and the server replay would not. Spell resolution offers a presentation-only acceptance hook after its rule checks. Small copy edits in `object.js` explicitly identify up/down stairs and dry fountains; `fountain.js` announces that draining leaves no water. Fountain prompts use “wash.” The original draining checks still replace the fountain tile with `ODEADFOUNTAIN`, and the existing floor-state save path persists that object unchanged. Combat, monster AI, stair-transition rules, and progression rules are otherwise unchanged.

Known floor and wall tiles are GPU-instanced from 12-triangle boxes. Empty floors and walls do not spawn a scene-graph Group; only items, landmarks, and creatures do. `src/ambient-rats.js` keeps a fixed pool of two decorative wall-top rats outside actors/props so pick, combat, and inventory never see them. Each wears a clone of `public/models/creatures/rat.glb`, a skinned rat that `scripts/build-rat.mjs` models, rigs and animates without downloads (see [docs/art/models.md](docs/art/models.md)); it loads on the first cave floor, and placement never waits for it. One `AnimationMixer` per rat cross-fades between a looping resting habit (sniff, groom, rear or idle) and a trot while it scurries, turning toward the next tile. Fur is a per-rat material tinted from the tile, with a faint emissive lift so dark tints read on flat cave stone; skin, geometry and the soft oval shade beneath are shared. Size, tint, habit and resting facing come from the tile the rat appears on and stay with it while it scurries, and the pair stays several tiles apart. Revealing more wall on the same floor keeps placed rats on their tiles. Town skips them, and only near-camera scurries briefly keep the frame loop awake. Static terrain and buildings in both the title scene and gameplay are merged by material; reusable model geometries are shared and kept to low segment counts (boxes instead of rounded boxes, 80-triangle orbs, 128-triangle rings). Distant title and town terrain does not cast shadows, and the dungeon footprint slab does not either. Replaced merged geometry and landmark textures are disposed when levels change. Shadows update when the scene or wall layout changes, not on every camera-side cutaway, and Balanced does not refresh the shadow map while the hero walks. Camera-side cutaway only lowers the wall column between the camera and the hero, and town plaza walls stay full height so walking past them does not open a hole. Balanced rendering skips the PMREM environment, MSAA, extra torch point lights, and the hero point light (town and dungeon); uses Lambert floors/walls without bump maps; keeps wall tiles from casting shadows; caps the pixel ratio below native DPR; skips rebuilding unchanged floor/wall/prop structure on a walk step; never allocates the bloom composer; and raises cave ambient, sun, and fill so a dungeon stays readable without those point lights. Cinematic restores richer materials, full contact shadows that follow the hero, a half-resolution bloom pass, and output color conversion. In caves it lights the stone for real (`src/cave-light.js`): floors, walls and caps switch to the lit PBR surfaces with their color, relief and roughness maps, and the only light is the hero's lantern, the nearest wall torches, the three candles nearest the hero (`CAVE_LIGHT.candle`: short-reaching, quick to waver, no shadows, from a fixed pool so lit materials never recompile) and a dim, cool bounce (hemisphere 0.3). Point lights fall off by the inverse square of the distance to a light a tile across (`LIGHT_SIZE`, patched into three's shared `lights_pars_begin` before anything compiles): from a point, light grows without bound up close, and a torch's light hangs inside the walkable tile beside its wall, so creatures there and the hero under the lantern burned white. Intensities are set for that size. The lantern hangs above the hero and a little toward the camera, so the side the player sees is lit and shadows fall away from view; its cube shadow (1024) redraws when the hero or the lantern moves, including when the view turns. Torch shadows hold only walls and caps (`OCCLUDER_LAYER`). three's shadow pass tests layers against the viewing camera, so `renderTorchShadows()` draws them in a pass of their own, only when a torch moves or the walls change: the camera sees only that layer, only the torch maps are marked, and the frame goes to a 1×1 target. Torchlight therefore stops at stone instead of reaching into the next corridor. A dim cave environment (black, with a warm band of distant torchlight) gives armor and blades something to reflect and lights the sides the lantern misses (`CAVE_LIGHT.reflection`), so a creature between the hero and the camera never shows a black front, while floors face its black sky and keep their dark, replacing the town's studio reflection, which `applyLevelLighting()` now switches per floor. Volcano basalt glows from an emissive map of its fissure cores. Every KayKit triple candle burns in every tier (`src/candle-flames.js`): a shader-drawn teardrop flame on each measured wick that sways, stretches and brightens on its own beat, over a soft halo; Cinematic raises their heat past the bloom threshold. The first frame on a cave floor lets the lantern draw its shadow map inside the torch-shadow pass, because the lit walls there sample it and an empty shadow sampler fails the draw. The Cinematic town is late afternoon (`TOWN_LIGHT` in `src/lighting.js`): the shadow-stabilized sun sits low in the south-west, and a physical `Sky` replaces the studio `RoomEnvironment`, so shade takes the sky's blue and water reflects it. Caves raise the exposure to 1.25 and bloom from a lower threshold, so flames and lava bloom while the town keeps its faint glow. Auto and Balanced caves stay flat. The marketing home preview always runs Balanced so a leftover Cinematic preference cannot bloom-lag the landing page. It disables scene input so the background cannot capture page scrolling, stops frames when off-screen/hidden (including after resize/context recovery), and renders a still scene under reduced motion. Entry styling lives in `src/entry.css`; eight small WebP class portraits are rendered offline from the rigged heroes rather than adding live renderers. Saved expeditions expose Continue before new-game configuration, while name, difficulty and multiplayer retain their existing adapter paths. Marketing sections remain visible without JavaScript. On context loss, the renderer releases GPU resource registrations while retaining CPU-side geometry and materials. Restoration reuploads that artwork and regenerates the reflection environment when cinematic. This prevents stale-handle deletion errors during later WebKit level changes, quality changes, and resizes. Read-only `ularnGraphics.metrics()` reports rendering, frame limits, idle state, sprite/effect pools, active lights, floor/wall instance counts, prop groups, shadow update counts, floor material type, bloom/composer allocation, lighting intensities, and GPU resource counts for diagnostics. The WebGL renderer requests a high-performance GPU. Camera orbit, zoom, and walk follow `requestAnimationFrame` without an extra timeout throttle so panning stays vsync-smooth. Motion samples the frame's vsync time; long frames advance in real time up to 100 ms, and orbit damping and creature turning are scaled by frame time. Rotate, zoom and reset ease the orbit over 140 ms; the hero is framed between the top bar and dock at screen center, leaving center only to stay 160 px clear of a floating side panel (`FRAME_CLEARANCE`); panels that change the play area slide the framing, while window resizes reframe at once. An Auto resolution change waits until the hero and camera settle. Balanced still stops drawing once the scene settles, and Cinematic idles at 12 FPS, or 30 while flames, torches or lawns keep moving (`SetDressing.update` says so; reduced motion holds them still). `metrics()` also reports `updateP95`, `longTasks`, `stepJitter` and the latest walk's `heroSpeeds`. Hidden windows stop frame scheduling. Floor-loot sprites flood-fill pale generated cards out of their alpha so items do not sit on a white plate, then bleed edge colors into transparent pixels and sample trilinear mipmaps. Transient spell and fountain lifetimes use wall time to expire correctly even on slow hardware. Per-frame work faces only billboard sprites and draining fountains rather than walking every tile group. Both maps show the whole floor. The compact one never scrolls: `src/map.js` draws it at the panel's own resolution from the same charted tiles as the expanded map, and the hero's marker moves across it. Green and red arrows point from the hero toward the nearest charted way up and way down (`stairCompass`: the targets of `<` and `>`, dead ends skipped; the map glyphs share `STAIR_COLORS`). The maps paint known tiles instead of filling every unexplored cell, and walking only rewrites the old and new player cells when the charted content is unchanged.

Merged rendering uses `ChunkedTerrainMesh` to preserve the existing matrix/color, wall-cutaway, terrain-tint and raycast interfaces while uploading changed 8×8 chunks. `StaticTiles` batches compatible scenery while preserving source groups for picking and item identity. Auto quality adjusts only resolution (0.65/0.75/1.0 caps, then 1.5 and 2.0 on screens dense enough for them, never above the device pixel ratio) after sustained active overload/headroom, remembers the tier per device, and keeps MSAA at every tier; its higher tiers retain the lightweight renderer. Cinematic explicitly adds shadow maps, bloom, SSAO and SMAA. Performance samples use actual active elapsed time so clamped animation steps cannot hide long stalls. Shared wall geometry bakes height-based shading into its existing vertex colors, contact fans feather their existing vertex alpha, and procedural color/normal/roughness maps share one logical pattern at every resolution. No per-turn texture regeneration or extra draw pass is introduced. The current north camera, 140 ms collision-aware steps with restrained body motion and articulated knees/ankles, flat mapped caves, loot artwork, ambient rats, and cooperation aura remain. Town cinematic lights use stable fading assignments and snapped shadow texels.

## Game feel

Feedback only observes. The bridge adds two wrappers that read rule state before and after the original call and dispatch an event; they never call the engine RNG, `millis()` or `nap`, and write nothing. `ularn:damage` wraps `hitm` (every player-inflicted damage path) with the amount, a kill flag, experience, the species' engine cap `monsterlist[arg].hitpoints` and `weapon` or `spell` as the source. `ularn:hurt` wraps `hitplayer` with the amount, a miss flag and the attacker. Both are emitted only for visible tiles, keep mimics disguised, and carry `self` so rooms ignore other adventurers. The snapshot adds the monster cap `hpMax` (null for mimics), `kills`, `spellsKnown`, `deepest`, `xpFloor`, inventory `arg`/`known`, and `ending`, a summary captured where the engine writes its score. A seeded melee golden (`tests/lib/combat-fixture.mjs`) runs headless without the bridge and in the browser with every listener attached; their checksums must match.

`src/feedback.js` is the director, a pure module. Listeners only enqueue; each authoritative update runs `begin` (room catch-up bursts and the floor veil), `applyEvents` before the world syncs (so a slain creature is marked before its actor is removed) and `applyDiff` after it (level-ups, floors, low health). Events map to small, medium and heavy tiers of trauma-based shake (trauma² × layered sines, added to the existing screen-space view offset so picking, follow and cutaways never see it) and presentation hit-stop. Hit-stop holds `PresentationClock`, which drives hero swings and casts, flinches and corpses. Walking, the camera and input run on real time, and holds are capped at 120 ms per second. Large beats such as level-ups queue 1.5 s apart. A monster's reply to a swing lands after the blade connects.

`src/impact-effects.js` pools the 3D half. A hit flash swaps in a cached clone of each creature material that differs only in its emissive uniform, so no program compiles and shared materials are never mutated. Flinches and lunges are offsets on the actor glide. A creature the engine reported slain moves to a corpse pool outside `actors` (never picked), topples away from the blow and sinks below the floor; one that merely left sight still vanishes. Items that appear on an already-charted tile pop out of the floor; level-ups and victory raise an additive light column, ring and sparks. `src/combat-effects.js` adds an impact spray and soft flash where a spell lands. Effects report live only while animating, so Balanced and Auto still stop drawing, and they clear on floor changes, pauses, hidden tabs and context loss. Cinematic alone adds cave dust, volcano embers and a breathing hero torch; Balanced and Auto caves stay flat.

`src/feedback-hud.js` is the DOM half: pooled damage numbers that follow world points through an allocation-free `projectInto` frame hook, a nameplate with a four-step wound band (exact monster health is never shown), the screen-edge wound and low-health vignette, level-up and depth cards, pickup flyers using the already-stripped floor art, a gold count-up and corner notices. The floor change happens under a short veil and never delays input. Settings live in `ularn3d.feel.v1` (`src/feel-settings.js`): screen shake, reduced flashing, damage numbers, enemy wound bars and motion (system, full or reduced). Reduced motion keeps numbers, banners and cards but drops shake, hit-stop, knockback and slides.

Death plays out before the engine modal opens: the hero collapses, the camera pushes in without saving that zoom, and a saturation veil drains the world. Any key skips it. The recap (`#run-recap`, inside the engine modal so Enter still reaches `endgame`) shows the killer, score, deepest depth, kills, turns, personal-best chips and a local rank. R tries again with the same name, calling and difficulty: `sessionStorage` carries the hero across one reload, because the engine starts only once per page. C returns to the title, which preselects the last calling and difficulty. `src/profile.js` keeps `ularn3d.profile.v1` apart from saves: lifetime records, per-calling bests, 30 recent runs, species seen and slain, and feats from `src/feats.js`. Runs are recorded once by game ID. Rooms and spectators never write it. `src/bestiary.js` shows all 66 portraits, as silhouettes until met. The journal colors lines by kind (`src/journal.js`). The caves frame closer than town (5.8 across and 10 up, against town's 8.9 and 15.5, at the same pitch), and each region remembers its own zoom in `ularn3d.camera`. Cave zoom lives under `caveView`; the earlier `caves` entry held the farther framing, saved every turn, so it is dropped once. Re-centering saves to the region being played.

## Flow and controls

`src/next-step.js` is pure. After each update `main.js` hands it the snapshot and the engine's own contextual buttons (read from `#CONTEXT`, keys included), and renders one prompt above the dock. A creature in reach comes first (moving into it attacks), then the tile underfoot (Enter the caves `E`, Go down `>`, Take `t`; pack-wide buttons such as known items are skipped), then a goal: known unblocked stairs, the dungeon entrance, the volcano shaft once Depth 15 has been reached, the Eye or the cure on their floors, or the way home once the cure is carried. A click presses the same ordinary key, or walks a known route with the existing travel; rooms and switched-off travel preferences drop the key and keep the route. Auto explore never opens doors, because opening one can shock or weaken the hero, so when no reachable known ground borders the unknown but a closed door does, the goal becomes "Walk to the door". Beside one shut door (and no chest), Open names its direction and opens toward it through `openToward` without asking. At half health or below with no hostile creature in sight, Rest (`M`, the engine's own wait-until-recovered) comes first; rooms never suggest it. Prompts, menus, endings and spectating hide it.

While the engine asks for a direction (`ularn.promptKind()` is `direction`), the interaction panel swaps the engine's pack-command row for eight direction buttons; casting titles it "Cast a spell". `src/terminal-pick.js` reads the engine modal's text: a choice written as `a) leather armor` lights under the pointer (the CSS Highlight API) and a click presses its letter, so stores, the college and the trading post take clicks. The town destination list uses the building sign names and gives focus back to the game after a pick.

`src/gamepad.js` reads the standard mapping only while a pad is connected. In play the stick or d-pad drives the same `HeldMovement` as the arrow keys (a lone d-pad direction settles for 60 ms so diagonals are not read as two steps), and buttons call HUD actions: A the next step, B cancel travel, X explore, Y inventory, bumpers rotate, triggers zoom, View map, Menu pause, L3 wait, R3 center. An engine direction prompt takes single direction keys; any other surface (title, dialogs, the engine modal and recap, choice prompts) moves focus spatially, A activates, B closes or sends Escape. Keyboard or pointer input hands the prompt glyphs back.

The title focuses Continue or Begin, so Enter starts. `ularn.saveSummary()` reads the saved `GameState` (decompress and parse only) for the hero, depth, level and time left on Continue; `ularn.promptKind()` reports whether the open prompt wants a direction. Each run measures new floors against `profile.deepest` from earlier runs: the first floor past it raises a notice and the depth card says so.

## Multiplayer

`src/online/rooms.js` contains authenticated RPC adapters. Protocol-two rooms start through `start_room`, which requires two connected players, checks readiness (hosting or joining marks a player ready; they can cancel), and freezes seed, difficulty, names, classes, and room slots. `send_room_action` derives the actor and user ID from membership, orders actions under the room lock, limits request bursts, and deduplicates retries by request UUID. `public.room_actions` is immutable to browser clients and protected by RLS.

`src/online/live.js` follows this authoritative log. Private Postgres Changes notifications accelerate updates; `sync_room` provides polling fallback, heartbeat, membership/chat updates, and paged catch-up. No peer broadcast, claimed user ID, state snapshot, or chat name drives the game. Native party helpers initialize distinct adventurers and apply each action to its room slot. Prompts remain with their owner. Rendering selects this browser's adventurer temporarily and restores the simulation actor. Auto-loot is personal; aura state is shared. Holding movement keeps at most one movement request in flight.

Join, leave, resume, and permanent removal are replayable lifecycle events. Reload uses the saved room reference and authenticated membership. Disconnected places expire after two minutes; expired or removed characters cannot keep an expedition alive. The room UI exposes invite copying, membership, host transfer/removal, and leaving. Host absence is handled by server election, while the ordered log allows gameplay to continue. Spectators follow a living room slot and its fog, with gameplay controls disabled. Online sessions never overwrite solo saves.

`src/online/chat-ui.js` owns chat presentation, quick sends, drafts, keyboard focus, channel guidance, delivery errors, and unread indicators. Messages come from authenticated chat rows. `submit-score` uses server-recorded protocol-two actions and the frozen character configuration; forged client logs cannot determine the score. The bounded verifier remains limited to 1,200 actions and its CPU budget. Protocol-one API/broadcast compatibility remains for existing frontend deployments during rollout; protocol two never consumes broadcasts.

## Persistence

The autosave key is `ularn3d.expedition.v1`. Saves contain a version, the engine's complete `GameState`, and optional equipped-slot indices, compressed with the bundled LZString library. Equipped-slot metadata distinguishes identical items so the exact wielded/worn objects survive reload; existing version-one saves without this metadata remain readable. Saving only happens between stable turns: never during a blocking callback, animation, or after death. Walking marks the in-memory dirty flag and schedules a coalesced two-second worker capture; the `GameState` capture itself runs in the next idle period (at most 50 ms later) so it does not land in the middle of drawing a walk. Compression runs in the worker, guarded by capture generations; explicit Save, Save & Exit, tab hide, page unload, and graphics loss save synchronously and invalidate older worker jobs. Manual and exit saves remain synchronous to avoid losing pending state. The original `S` command is adapted to save without invoking the legacy save-and-die path. The 3D journal keeps a deep scrollable history soft-capped at `LOG_JOURNAL_CAP` (2000) so LOG, snapshot log views, and journal DOM cannot grow without bound on very long expeditions; classic terminal display still shows the last `LOG_SIZE` lines. Snapshot reuses the log array between paints when unchanged, and `world.update` trusts bridge `structureRev`/`actorRev` so quiet known-floor walks skip re-hashing every tile.

Resume calls the original `loadState` after structural validation, avoiding legacy save deletion. Each start attempt resets monster-template combat values to their originals; both new games and resumes then run the original difficulty calculation exactly once. Saved individual monsters retain their own health and combat values. All original save-slot, backup, checkpoint, and winner-mail keys are redirected to a `ularn3d.legacy.` prefix; periodic checkpoints and endings therefore preserve classic save slots. Preferences and local leaderboard handling remain as before. Save errors dispatch a presentation event immediately. Informational telemetry is disabled; original error/warning diagnostics remain visible in the local browser console. The 3D door shortcut sends the original Open command and its requested direction synchronously; it sends no direction when the original rules reject Open. Enter/Space activate focused interface controls through the browser while other gameplay commands retain their engine mapping. The UI interrupts both its own route timer and the native engine explorer when pausing, opening help, or hiding the page. Input is also gated while a dialog is open or graphics are unavailable. Original local score handling is retained. The menu and `z` command expose the Supabase leaderboard with a local-records toggle, upload status, and visible score details. Recorded replays and larn.org's weekly challenge server are not attached to this fork. The title screen's Weekly challenge replaces that server locally: the bridge derives a seed from the ISO week label (`getGotwLabel`, e.g. `2026_43`), and that seed picks the calling and a difficulty from 1 to 3. On start it runs the seeded engine host through hero creation, builds all 21 floors and rerolls the store's spellbook, as `uploadGOTWforDate` once did on the server, then removes the host so play stays unseeded. `GOTW` keeps new floors unseen, and the bridge skips the engine's return-visit monsters on a floor's first arrival, so no floor depends on earlier actions. The week and a practice flag travel in the autosave, so Continue resumes a weekly run. `ularn3d.weekly.v1` remembers this browser's counted run for the week (game ID `w<label>-<random>`). Later runs that week are practice: they show the run recap but are never written locally or to Supabase, like the engine's `DIED_RETRIED_GOTW` games. Weekly rows carry `details.gotw`, and the weekly board filters `ularn_scores` with `details->>gotw=eq.<label>`, so no migration is needed. `score-service.js` and `scores.js` are in the submit-score edge bundle, so `node scripts/build-submit-engine.mjs` regenerates it; rooms never run a weekly challenge, so the deployed function behaves the same either way.

## Deployment

`npm run build` produces `dist`; Vercel serves those static files. Public entry points are the [home page](https://ularn-3d.vercel.app/), [browser play](https://ularn-3d.vercel.app/play/), the [field guide and history](https://ularn-3d.vercel.app/about/), [What’s New](https://ularn-3d.vercel.app/changelog/), and the optional [Windows executable](https://ularn-3d.vercel.app/downloads/Ularn.windows.exe). The classic fallback is served directly from `/engine/larn_local.html`. These are real files and directory indexes, so no SPA wildcard rewrite is needed. Source scripts and the original engine license are kept with the project. `package-lock.json` pins dependencies. Production deploys for `helloivanco/ularn3d` target the Vercel project that serves `ularn-3d.vercel.app`.

The game and guide contain canonical URLs, descriptions, Open Graph/Twitter metadata, and JSON-LD. Their shared social image is `public/social/ularn.png`. `public/robots.txt` points to `public/sitemap.xml`, which lists `/`, `/play/`, `/about/`, and `/changelog/`. Curated player notes live in root `CHANGELOG.md` and the marketing What’s New page; [GitHub Releases](https://github.com/helloivanco/ularn3d/releases) hold the full artifact history. `vercel.json` redirects duplicate document/guide URLs to their canonical paths, sends legacy `/credits` URLs to `/about/#history`, marks `/engine/` and `/downloads/` responses as non-indexable, and sends attachment/content-type headers for `Ularn.windows.exe`. The published URL path is stable across releases; Vercel redirects it to the GitHub Release asset `Ularn-${version}.windows.exe` for the current `package.json` version so Git deploys cannot omit the binary. The play page, field-guide footer, JSON-LD, and Electron package display that same version. Each product release runs `npm version` so those surfaces cannot keep a previous number.

The Electron host in `desktop/main.cjs` serves `dist/` through `ularn://game/`, with a sandboxed renderer, no Node integration, and a persistent `Ularn` profile. Remote requests are blocked except GET, POST and OPTIONS on `/rest/v1/ularn_scores` at the configured Supabase origin; the CSP permits that origin while the request policy restricts paths and methods. `desktop/protocol.cjs` confines local requests to packaged assets and resolves directory URLs such as `/about/` to their `index.html`. Closing the app saves the last stable turn before flushing storage. Desktop and browser saves have separate storage origins.

`desktop/electron-builder.yml` produces the self-contained Windows x64 portable `Ularn.windows.exe`, plus optional app-folder, ZIP, and installer targets. Its pinned NSIS `1.2.1` bundle includes a native Apple Silicon compiler, so the portable executable can be cross-built without Rosetta. `npm run desktop:package:win:portable` builds the game and executable; `npm run desktop:verify:portable` extracts that executable, verifies all embedded runtime files and game assets against the local build, and writes its SHA-256 sidecar. The Windows GitHub Actions workflow builds and verifies artifacts, and a push to `main` publishes the versioned portable file as a GitHub Release. See [DESKTOP.md](docs/DESKTOP.md).

The executable is Git-ignored, so a source-only Vercel Git build cannot embed it. The site keeps `/downloads/Ularn.windows.exe` and redirects that path (and the checksum) to the GitHub Release for the current `package.json` version. Desktop packaging still excludes `dist/downloads/`, preventing recursive executable payloads; `.vercelignore` excludes the separate `release/` working directory.

Optional local prebuilt deploys can still stage a verified executable under `public/downloads/` before `vercel build --prod`. The exact commands are in [README.md](README.md#build-and-vercel). GitHub Releases are the hosted download used by production.

## Validation boundaries

Playwright verifies actual browser input, presentation state, and serialized reloads. Fixtures seed difficult-to-reach scenarios such as demon visibility, death, and quest completion, then exercise the original callbacks. No gameplay cheats or test-only endpoints are included in the UI. Automated verification reduces regression risk; it cannot prove that a large random roguelike has no defects.

Site checks cover the static guide, metadata, sitemap, and download links. Desktop tests cover local asset routing, traversal rejection, renderer isolation, first-launch storage creation, and saving through a complete Electron restart. Portable extraction verification proves the runtime payload is self-contained; macOS tests do not execute the Windows binary.

Seeded deterministic replay sessions retain the native rules and RNG stream; local solo lemming adapters apply only to ordinary unseeded 3D expeditions.
